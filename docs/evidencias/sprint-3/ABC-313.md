# ABC-313 · Verificación del inicio de una orden

Validación del 9 de noviembre de 2026 sobre `develop` en `ec2da81`, después de integrar ABC-337.

El inicio comprueba la última respuesta de disponibilidad y la receta activa. Dentro de la transacción, el servicio bloquea la fila de la orden y vuelve a verificar su estado antes de guardar el inicio y su historial. Si otra solicitud ya cambió el estado, la segunda recibe `409` y no escribe otra transición.

| Comprobación | Resultado | Entorno |
| --- | --- | --- |
| Regresión de Órdenes | 128 pruebas aprobadas, sin omisiones | Jest, con repositorios de prueba y casos HTTP con Auth simulado |
| Disponibilidad en frontend | 12 pruebas aprobadas, sin omisiones | Componentes React con respuestas simuladas |
| Compilación de Producción | Correcta | Nest |
| Inicio a través del gateway | 10 solicitudes verificadas | Gateway, Auth y Producción compilados, con migraciones y bases aisladas en PGlite |

La prueba de carrera simula que la primera lectura devuelve `PLANIFICADA` y la lectura bajo bloqueo devuelve `EN_PRODUCCION`. Antes del cambio, la solicitud continuaba y escribía una transición. Con el cambio, se rechaza y el intento no escribe en el historial.

La comprobación HTTP usó una sesión real del rol Encargado de Producción y respuestas de Inventarios cargadas como datos de prueba. Se verificaron estos resultados en `PATCH /api/produccion/ordenes/:id/estado` con `nuevoEstado: EN_PRODUCCION`.

| Caso | HTTP | Resultado observado |
| --- | --- | --- |
| Sin sesión | 401 | Inicio rechazado |
| Sesión sin `ordenes.iniciar` | 403 | Inicio rechazado |
| Orden inexistente | 404 | Inicio rechazado |
| Requiere 50 kg y hay 30 kg | 409 | Informa 20 kg de faltante |
| Consulta inexistente | 409 | Informa `SIN_CONSULTA` |
| Consulta pendiente | 409 | Informa `PENDIENTE` |
| Consulta pendiente con error de respuesta | 409 | Conserva `PENDIENTE` y bloquea el inicio |
| Receta inactiva con disponibilidad suficiente | 409 | Rechaza por receta inactiva |
| Requiere 50 kg y hay 50 kg | 200 | Pasa a `EN_PRODUCCION` y guarda fecha de inicio |
| Repetición del inicio sobre la misma orden | 400 | Rechaza porque ya no está planificada |

Las cinco órdenes bloqueadas por precondiciones quedaron en `PLANIFICADA`, sin fecha de inicio. La base contiene una sola transición `PLANIFICADA` → `EN_PRODUCCION` para la orden válida, con el actor autenticado. La cuenta de prueba fue dada de baja en la base desechable. La prueba HTTP cubre reintento consecutivo. La carrera se verificó en la prueba de regresión con repositorios simulados.

Para ejecutar las suites, desde `services/produccion-service`:

```sh
npm test -- --runInBand src/ordenes
npm run build
```

Desde `frontend`:

```sh

```

## 1. PostgreSQL real con el consumidor real (sin broker)

`src/demanda/demanda.verificacion.spec.ts` entrega los mensajes al
`PubSubDemandaConsumerService` como lo haría Pub/Sub y usa PostgreSQL 15 real
(`taller_postgres`) en un esquema temporal con las migraciones del módulo.

```powershell
cd services/produccion-service
$env:DEMANDA_DB_REAL='1'
npx jest src/demanda/demanda.verificacion
```

Resultado: **9 pruebas aprobadas, 0 fallidas**.

| Caso | Comprobado |
| --- | --- |
| Válido | Demanda RECIBIDA, 2 ítems e inbox PROCESADO confirmados **antes** del ACK; visible en `DemandaService.listar` (ABC-358) filtrando por origen y estado |
| Inválido (cantidad 0, unidad `cajas`) | ACK sin NACK, rechazo `EVENTO_INVALIDO` con ambos campos en el detalle, sin demanda |
| Repetido | Redelivery del mismo eventId y mismo pedido con otro eventId: una demanda y un ítem |
| Contradictorio | Rechazo `DEMANDA_CONTRADICTORIA`; la demanda válida conserva su fecha |
| Concurrente, misma demanda | Dos eventos simultáneos: una demanda, ambos ACK |
| Concurrente, mismo eventId | PROCESADO + DUPLICADO, una fila de inbox |
| ACK perdido tras el commit | NACK; la redelivery responde DUPLICADO con ACK, sin doble efecto |
| Fallo transitorio de la base | NACK sin escribir; la entrega posterior se procesa |
| Mensaje no JSON | ACK sin bucle |

Regresión de Producción: ver la ejecución completa en el commit.

## 3. Publicación real en Google Cloud — PENDIENTE

Requiere un proyecto de Google Cloud con el topic y la suscripción de Producción,
y una cuenta de servicio con permiso de publicación. Con eso, el mismo script
publica en Google real (sin `PUBSUB_EMULATOR_HOST`):

```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS='C:\ruta\a\cuenta-servicio.json'
$env:GCP_PROJECT_ID='<proyecto>'
$env:PUBSUB_DEMANDA_TOPIC_ID='<topic de ventas>'
Remove-Item Env:PUBSUB_EMULATOR_HOST -ErrorAction SilentlyContinue
cd services/produccion-service
npm run demanda:publicar-prueba
```

El script imprime por cada caso la fecha/hora, el `messageId` de Google, el
`eventId` y el cuerpo completo: es la evidencia que exige la subtarea. Producción
debe correr con `PUBSUB_DEMANDA_CONSUMER_ENABLED=true` y la suscripción real.
El contrato `DemandaRegistrada.v1` sigue pendiente de confirmación con Ventas.

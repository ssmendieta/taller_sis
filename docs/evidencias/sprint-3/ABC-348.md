# ABC-348 · Procesar resultado de Contabilidad

El consumidor confirma mensajes malformados como error permanente, incluidos
`null`, arreglos y números aunque tengan atributos. Ante fallos transitorios
pide reentrega. Si un cierre ya es final, el registro de un mensaje tardío
queda como `IGNORADO` y devuelve el estado persistido en el cierre.

Ejecutadas 20 pruebas (7 del consumidor, 8 de persistencia y 5 del contrato) con entregas
simuladas de mensajes y una base SQL aislada PGlite. La suite instala también
la migración de columnas de reintento del inbox de demanda, compartido por
Contabilidad. Se comprobó persistencia de `RECIBIDO` y `RECHAZADO`, motivo,
correlación, mensajes duplicados, respuesta tardía y recuperación tras caída.
La compilación del servicio pasó. El broker de esta prueba se simula.

```powershell
$env:CONTABILIDAD_DB_REAL='1'
npm test -- --runInBand src/integraciones/inbox/resultado-contable.persistencia.spec.ts src/integraciones/inbox/pubsub-contabilidad-consumer.service.spec.ts src/integraciones/contratos/contabilidad-v1.validator.spec.ts
npm run build
```

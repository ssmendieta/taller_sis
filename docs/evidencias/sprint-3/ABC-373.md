# ABC-373 · Aceptación y regresión de asignación de rutas

Verificación del 11/11/2026 sobre `RamaAndrea` en `90dba3b`, que incorpora
`develop` en `f7fe29c`, más los cambios de esta subtarea. HU: ABC-368.

## Alcance comprobado

La suite `services/logistica-service/src/rutas/rutas.aceptacion.spec.ts` tiene
30 casos nuevos. Usa HTTP de Nest con `RutasModule`, guard, pipe, clientes,
repositorios y validador de asignación reales, y PostgreSQL nativo con las 12
migraciones existentes. No se sustituye la base ni se simulan los bloqueos.

Auth, ERP y Producción son **simuladores HTTP locales** de la suite: la sesión
de prueba no es una credencial de un usuario real y los recursos/unidades son
datos controlados. Este resultado no demuestra la disponibilidad del ERP real,
el despliegue Docker ni una publicación en Google Cloud Pub/Sub.

## Resultado reproducible

Desde `services/logistica-service`, apuntando a una **base PostgreSQL de prueba**
mediante `DB_HOST`, `DB_PORT`, `DB_USERNAME`, `DB_PASSWORD` y `DB_DATABASE`:

```powershell
$env:LOGISTICA_DB_REAL='1'
npm test -- --runInBand src/rutas src/recursos-externos
npm run build
```

- 13 suites, **206 pruebas aprobadas**, ninguna omitida.
- Incluye los **30 casos nuevos** con HTTP y PostgreSQL real y la regresión
  existente de rutas, capacidad, cliente ERP, respaldo y consulta de recursos.
- Compilación de Logística correcta.
- El esquema `abc373_*` y la restricción auxiliar para el caso de fallo SQL se
  eliminan al terminar. No se alteran tablas de otros esquemas, usuarios ni
  permisos. La prueba no publica mensajes ni reserva recursos en el ERP.

## Ampliación después de integrar ABC-372 (12/11/2026)

Base: `develop` en `b01f1b93ede584a4b79892a149e04d9d591bfebb`.
Se añadió `frontend/scripts/rutas-integracion-real.test.mjs` sin nuevas
dependencias ni cambios de código de negocio. La suite utiliza RutasPage,
sus componentes y logisticaService originales con React Test Renderer; todas
las solicitudes de Logística usan fetch y HTTP reales hacia Nest. Incluye las
14 migraciones actuales de Logística en un esquema temporal `abc373_ui_*`.
Auth, ERP y Producción son simuladores HTTP locales explícitos.

Los 9 casos comprueban creación desde el formulario y persistencia, edición
con boletas propias, recuperación tras reiniciar API y pantalla, rechazo visible
de sobrecapacidad, unidad incompatible y boleta anulada, recurso ocupado,
despacho concurrente con una edición abierta y permisos 401/403. Los errores
conservan el formulario y no dejan rutas parciales.

```powershell
# Variables DB_* apuntando a PostgreSQL de prueba.
# Se requieren las dependencias de frontend y logistica-service.
$env:LOGISTICA_DB_REAL='1'
Set-Location frontend
node --test scripts/rutas-integracion-real.test.mjs

npm run build
Set-Location ../services/logistica-service
npm test -- --runInBand src/rutas src/recursos-externos

```

Resultados de esta ampliación:

- Integración React + HTTP + PostgreSQL: **9 aprobadas**, ninguna omitida.
- Regresión API y recursos con PostgreSQL: **14 suites, 215 aprobadas**,
  ninguna omitida; incluye los 30 casos de aceptación originales.
- Suite frontend de ABC-372 con API simulada: **14 aprobadas**.
- Compilación del frontend y Logística: correcta.

Se ejecutó con PostgreSQL 15 nativo en una instancia aislada de prueba.
La suite solo crea y elimina su propio esquema. No publica mensajes, no usa
cuentas reales y no modifica permisos. El renderizado es un árbol React de
prueba, sin navegador: esta evidencia verifica el recorrido funcional de los
componentes, no su apariencia visual. La revisión visual, el arranque de los
contenedores y las capturas del despliegue corresponden a ABC-403.

# Evidencia local — ABC-366

**Subtarea:** [ABC-366](https://ucb-team-h8yk3x85.atlassian.net/browse/ABC-366) — Endpoint de demandas planificables  
**Rama:** `RamaSergio`  
**Fecha:** 07/11/2026

## Propósito

Separar las demandas meramente recibidas de las que ya fueron confirmadas y pueden utilizarse
para planificar producción. La consulta no crea órdenes ni modifica el estado de una demanda.

## Plan ejecutado

1. Incorporar `origin/develop` en `RamaSergio`.
2. Crear `GET /demandas/planificables`, protegido por `ordenes.consultar`.
3. Forzar `estado = CONFIRMADA` en el servidor y rechazar el parámetro público `estado`.
4. Mantener filtro por origen, paginación y resultado único aunque la demanda tenga varios ítems.
5. Separar en `DemandasPage` las vistas **Recibidas** y **Planificables**.
6. Validar backend, frontend y compilaciones.

## Criterios de aceptación

| Criterio | Resultado |
| --- | --- |
| Una demanda `RECIBIDA` no es planificable | Cumplido: el servidor fuerza `CONFIRMADA` y no acepta `estado` |
| Una demanda confirmada aparece una sola vez | Cumplido: unicidad de demanda existente y consulta `DISTINCT` |

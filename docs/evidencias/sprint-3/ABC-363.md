## 1. Alcance verificado

| Criterio de ABC-128 | Verificación |
| --- | --- |
| CA-01: prioridad determinista y desempate por fecha e ID | `reglas/prioridad.spec.ts`: orden, desempate numérico, independencia del orden de entrada y fechas inválidas |
| CA-02: solo solicitudes activas y compatibles | `reglas/compatibilidad.spec.ts` y prueba real que rechaza destinos incompatibles sin persistencia parcial |
| CA-03: una solicitud no pertenece a dos grupos activos | Dos llamadas reales y concurrentes a `AgrupacionService.agrupar`; exactamente una termina y el índice `uq_grupo_solicitud_activa` conserva una sola pertenencia activa |
| CA-04: agrupar/desagrupar es atómico y registra autor y fecha | Lectura posterior de `grupos_salida` y `grupos_salida_solicitudes`; se verifican autor, fechas, liberación conjunta y posibilidad de reagrupar |
| CA-05: operación desde la interfaz y grupo despachado inmutable | Componente React real contra API simulada; además, prueba con PostgreSQL real rechaza deshacer un grupo asociado a una ruta despachada y conserva sus miembros |

Los estados no agrupables, incluido `ANULADA`, se prueban en la regla pura. La tabla actual de solicitudes solo admite `BORRADOR` y `PREPARADA`, por lo que no se inserta artificialmente un estado que violaría `ck_solicitud_salida_estado`.

## 2. PostgreSQL real: persistencia y concurrencia

Archivo: `services/logistica-service/src/agrupacion/agrupacion.persistencia.spec.ts`.

La suite crea un esquema temporal `abc363_<pid>_<fecha>`, ejecuta las diez migraciones de Logística y elimina el esquema al finalizar. Producción se sustituye únicamente para resolver la unidad de carga; las transacciones, bloqueos, restricciones e índices son PostgreSQL reales.

Casos ejecutados:

1. Persistencia de grupo, miembros, autor y fecha.
2. Desagrupación atómica, liberación de miembros y desvinculación de una ruta planificada.
3. Reagrupación de solicitudes liberadas.
4. Rechazo de solicitudes incompatibles sin filas parciales.
5. Dos agrupaciones concurrentes con una solicitud compartida: un éxito y un conflicto.
6. Rechazo de desagrupación para un grupo despachado, sin alterar grupo ni miembros.

Comando:

```powershell
cd services/logistica-service
$env:RUN_DB_INTEGRATION='true'
npm.cmd test -- --runInBand src/agrupacion
```

Resultado:


## 5. Resultado

Los criterios de aceptación de ABC-128 cubiertos por ABC-363 quedan verificados. PostgreSQL impide la pertenencia múltiple incluso con llamadas concurrentes; la desagrupación conserva trazabilidad y atomicidad; y un grupo despachado permanece inmutable tanto en el servicio como en la interfaz.

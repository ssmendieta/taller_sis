# ABC-438 — Evento del lote conforme en el outbox

Fecha: 23 de noviembre de 2026. Base: `develop` en `60c3005`.

La creación de un lote conforme ahora guarda `ProductoTerminadoIngresado.v1`
en `eventos_outbox` con el mismo EntityManager y dentro de la misma transacción.
El evento contiene los identificadores y códigos reales del lote y la orden,
el producto, la cantidad con cuatro decimales y la fecha generada al persistir.
Se valida con el contrato de ABC-437 antes de guardar.

El evento queda `PENDIENTE`, con agregado `Lote` y el identificador del lote.
La restricción existente de agregado/evento impide dos eventos de ese tipo
para el mismo lote. Los intentos duplicados de crear un código conservan el
rechazo 409. No se hace ninguna llamada a Pub/Sub dentro de la transacción;
publicación y reintentos corresponden a ABC-439.

## Verificación ejecutada

- Suite de lotes y contrato del evento: **99 pruebas aprobadas** en seis
  suites, con `LOTES_DB_REAL=1` y PostgreSQL 16 en una base de prueba local.
  Incluye **33 casos de persistencia y HTTP con PostgreSQL real**.
- Se verificaron el payload y su validador, cantidad decimal y fecha exactas,
  conservación después de reconectar, rechazo del código duplicado,
  concurrencia y un evento por lote.
- Un CHECK de prueba provocó un fallo real al insertar el outbox: se comprobó
  que el lote también se revierte. Otro caso rechaza el lote por falta de
  conformes y comprueba que no aumenta el número de eventos.
- Se ajustaron los dobles HTTP para separar lotes y eventos, y el esquema
  aislado reutiliza la migración existente de outbox (1710000000017).
- `npm run build` de Producción: correcto.

No se probó publicación en Google Pub/Sub ni recepción por Inventarios.
La base de presentación y la integración completa se verifican al completar
las otras subtareas de ABC-411.
